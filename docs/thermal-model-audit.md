# Проверка тепловой модели, 2026-10-01

Численная реализация согласована с расчётным эталоном. Имеющиеся полевые
данные дают правдоподобную точку нагрева, но **не подтверждают точность
температуры поверхности и качество автоматического управления**. Полный
цикл на текущем гипотетическом банке показывает задержку старта и недогрев.
Модель остаётся включённой по запросу владельца; коэффициенты не подгонялись.

## Данные и воспроизводимость

Первичный CSV: `docs/autoheat-data-20260912-131954.csv` из коммита
`69cb0fc64f3c38f2811c6a4382c30d30446f161c`, 23 строки. Файл удалён в рабочей
копии; для проверки прочитан через `git show`, удаление не отменялось.
Температуры поверхности/мата в нём нет. Отметка «жарко» взята из раздела 7
спецификации, а не выведена из момента выключения в CSV.

Первичных файлов замера 14 сентября и поездки 12 сентября после 15:37 в
рабочей копии нет. Их выводы доступны только в спецификации и не были
независимо перепроверены по сырым данным. Фотографии также удалены из
рабочей копии; новые измерения по ним в этом аудите не извлекались.

Команды из корня, Python со стандартной библиотекой и JDK 17:

```bash
python3 docs/superpowers/specs/2026-09-10-auto-heat-thermal-model-reference.py
python3 tools/thermal-audit/audit.py > /tmp/thermal-audit.json
./gradlew test lint assembleRelease
```

Числа сохранены в [thermal-model-audit-results.json](thermal-model-audit-results.json).
Скрипт компилирует текущие Java-классы в временный каталог, сравнивает их с
Python и прогоняет настоящий `ModelHeatDriver`, включая подтверждения и тик.
Случайные прогоны воспроизводимы: seed `20261001`.

## Расчёт и реализация

- Эталон прошёл проверки сохранения энергии, направления теплообмена,
  остывания, ограничения подводимой энергии, задержки повышения и замкнутого
  управления. Это проверки заданных уравнений и сценариев.
- Погрешность шага 2 секунды против 0.5 секунды на переходных траекториях
  18 профилей: максимум **0.165 °C**, ниже принятого допуска 0.3 °C.
- Java против Python: **400** прогонов теплового шага на профилях банка с
  разными состояниями, уровнями, окружениями и длительностями. Максимальное
  расхождение — **4.98 × 10⁻¹³ °C**.
- **40** сравнений решений термостата для банков водителя/пассажира:
  расхождений выбранного уровня **0**.
- В шести 40-минутных синтетических поездках реальные для симуляции
  траектории всех выбранных профилей остались внутри оболочки наблюдателя;
  максимальная поверхность — **38.818 °C**. Повышения после предыдущей
  смены команды происходили не раньше трёх минут.

Последний результат относится только к синтетическим креслам из того же
банка параметров, который знает наблюдатель. Он не доказывает, что реальные
параметры автомобиля входят в этот банк, и не гарантирует предел 39 °C на
настоящем сиденье. Python-эталон не содержит Android-интеграцию и внешний
порог отключения: его хорошие результаты на одиночном профиле нельзя
автоматически переносить на приложение.

## Воспроизведение замера 12 сентября

По CSV: уровень 3 с **13:22:34 до 13:26:11**, ровно **217 секунд**;
салон 20.0 → 22.0 °C, улица около 18 °C по принятой формуле `raw/2 − 40`.
Для расчёта использовались точные времена событий и последнее известное
показание воздуха на каждом интервале.

Температура обоих узлов перед включением неизвестна. Ниже — отдельные
условные расчёты, в каждом мат и поверхность начинают с указанного значения:

| Начальное состояние | Базовый профиль в момент выключения | Банк занятого кресла |
|---|---:|---:|
| 17 °C | 39.76 °C | 32.65–43.95 °C |
| 20 °C | 40.26 °C | 33.77–44.02 °C |
| 23 °C | 40.73 °C | 34.84–44.09 °C |

Настоящий Java-наблюдатель при запуске без снимка, с неизвестной историей
от начала CSV, оценивает в момент выключения базу как **39.47–43.36 °C**,
банк — **32.23–44.46 °C**. Это диапазон гипотез, не измерительный интервал
с известной вероятностью покрытия.

Ощущение «жарко» совместимо с расчётом, однако **40 °C не были измерены**.
Совпадение с условным порогом 40 °C не позволяет заявлять ошибку модели
0.26 °C или калибровать по одной точке четыре параметра теплообмена.

Прежние словесные наблюдения также качественно совместимы с базовым
профилем: при −10 °C после 5–7 минут третьего уровня получается
37.24–40.15 °C; при +20 °C после 2–3 минут — 34.92–38.80 °C.
Но эти наблюдения уже участвовали в формировании исходных гипотез и не
являются независимой валидацией.

По описанию второго замера пустое пассажирское кресло грело слабее, чем
занятое. Причина не установлена: потери, контакт или мощность. Следовательно,
единый непроверенный коэффициент связи мата с поверхностью и конкретные
множители банка нельзя считать подтверждёнными для обоих состояний кресла.

## Поведение включённого управления

Во всех сценариях ниже физическое кресло в симуляции начинает с −15 °C;
параметры перебираются из текущего банка. Длительность — 40 минут.
«Неизвестная история» означает отсутствие снимка у наблюдателя.

| Сценарий | Первое включение | Поверхности профилей к 40-й минуте |
|---|---:|---:|
| Водитель, постоянные −15 °C, известный холодный старт | сразу, уровень 2 | 25.22–37.97 °C |
| Водитель, постоянные −15 °C, неизвестная история | **16-я минута** | 26.26–38.71 °C |
| Пассажир, постоянные −15 °C, известный холодный старт | сразу, уровень 2 | 21.14–37.97 °C |
| Пассажир, постоянные −15 °C, неизвестная история | **16-я минута** | 19.81–38.71 °C |
| Водитель, салон прогревается к +22 °C, улица −15 °C | сразу | 22.36–34.67 °C |
| Пассажир, тот же прогрев | сразу | 18.72–35.68 °C |

Задержка 16 минут — следствие гипотезы о недавно нагретом до 45 °C кресле,
которую без истории нельзя исключить. Подмена её холодным состоянием
скрыла бы неопределённость. Это реальное ограничение текущего алгоритма,
а не неисправный таймер.

При известном холодном старте происходит **18 переключений за 40 минут**,
включая первое. Несколько повышений до 2 сменяются нулём через 30–45 секунд
из-за промежуточного прогноза перегрева. Правило задержки повышения
соблюдается, но оно не гарантирует редких переключений вообще. Широкий
минимаксный банк защищает самые быстро греющиеся гипотезы ценой недогрева
других. Сузить банк по имеющимся данным обоснованно нельзя.

В сценарии прогрева окружение достигает порога **10 °C на 18.25-й минуте**,
и управление отправляет ноль. В реальном замере с салоном 20–22 °C этот
порог запретил бы автоматический нагрев вообще. Замер проводился вручную
и не подтверждает правильность такого продуктового порога. Порог сохранён
из существующей политики; его изменение требует решения о желаемом поведении.

## Исправление и пределы вывода

Найден и воспроизведён тестами дефект: `Air.reliable` принимал свежие `NaN`
и бесконечности. Они могли попасть в начальные состояния наблюдателя, а
следующее обновление отключало расчёт до перезапуска. Теперь они трактуются
как отсутствующее показание; для отсутствующей улицы используется салон,
для отсутствующего салона автоматика требует ноль, после нормального
показания расчёт восстанавливается. Добавлены две регрессии. После исправления
**157 тестов** проходят для каждой из debug/release, lint без ошибок
(26 предупреждений), release APK пересобран.

Для положительного заключения о комфорте нужны повторные размеченные
нагревы и остывания под человеком, известная история перед опытом и хотя бы
несколько независимых измерений поверхности. Одна субъективная отметка и
температуры воздуха не определяют `p`, `a`, `r`, `cₐ`, контакт, уставки и
смещение салонного датчика. Число опытов само по себе не гарантирует
идентифицируемость: нужна проверка на отдельных поездках, не использованных
для подбора параметров.
