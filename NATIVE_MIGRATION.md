запускается, интерфейс рисуется, температура салона показывается верно и

2. **`com.wt.airconditioner` действительно whitelisted**: CarService отдаёт

3. **Весь стек HVAC работает нативно**, включая подписку на события —
   температура обновляется без нажатия кнопки, значит `registerCallback` жив.

## Почему переписываем

Помимо белого экрана, из проекта уходит целый класс сложности: MethodChannel,
background isolate, `DartPluginRegistrant`, `@pragma('vm:entry-point')`, guard
на пересоздание `AndroidAutomotivePlugin`, второй Flutter engine внутри
`CustomAccessibilityService`. APK — **175 KB против 18 MB**.

Оценка объёма: `lib/` — 6207 строк Dart, из которых значительная часть
Flutter-специфики просто исчезает. Java-код плагина (1294 строки) переезжает
почти как есть, а Dart-обёртка над ним (1122 строки) удаляется целиком.

## Что сделано

Код в `native-probe/` — самостоятельный Gradle-проект, никак не связанный с
корневым `pubspec.yaml`. Чистая Java без androidx.

### Коммиты ветки

```
7d5f5f7  Этап 2: foreground-сервис и выключение по зажиганию
d11afb2  Правки пробника по второму ревью
4301a00  Правки пробника по ревью
1d926b3  Этап 1 миграции на native: пробник HVAC
```

### Файлы

| Файл | Роль |
|---|---|
| `CarHvacProbe.java` | мост к `android.car`: подключение, температура, уровни сидений, датчик зажигания |
| `SeatHeatService.java` | foreground-сервис — владелец соединения с `Car`, кольцевой лог, выключение по зажиганию |
| `MainActivity.java` | экран: статус, температура, кнопки 0/1/2/3 на сиденье, лог |
| `BootReceiver.java` | автозапуск сервиса после перезагрузки головы |
| `app/libs/android.car.jar` | стаб для компиляции, копия из `packages/android_automotive_plugin` |

### Ключевые решения и почему

- **Соединение с `Car` живёт в сервисе, не в Activity.** Закрытие экрана не
  должно рвать связь: на Android 13+ без foreground-сервиса процесс убивают, и
  автоматика молча перестаёт срабатывать.
- **`AccessibilityService` отсутствует и не появится.** Во Flutter-версии он
  существовал только чтобы поднимать background isolate; сервис плюс
  `RECEIVE_BOOT_COMPLETED` покрывают это штатно. Заодно снимается вопрос с
  «сервис работает неправильно» в Settings → Accessibility.
- **`applicationId` обязан быть `com.wt.airconditioner`** — с другим именем
  CarService не отдаёт `CarHvacManager`. Значит рядом с Flutter-версией native
  не встаёт, только вместо неё.
- **`android.car.jar` подключён через `implementation`, не `compileOnly`** —
  ровно как в рабочем плагине. Теоретически правильнее `compileOnly`, но цена
  ошибки здесь — потерянный цикл ручной прошивки.
- **Логи выводятся на экран**, в правую панель: adb-доступа к голове нет.
  Кнопка «Копировать лог» кладёт всё в буфер обмена.
- **Подписки на HVAC-события и на зажигание необязательны**: если любая не
  оформится, подогрев работает дальше, а в лог идёт строка о том, что
  отвалилось.
- **Событие зажигания без значения пропускается**, а не считается
  «выключено» — иначе пустое событие погасило бы подогрев на ходу.
- **Таймаут подключения 10 с** различает именно факт прихода
  `onServiceConnected`, а не готовность HVAC: иначе поверх настоящей причины
  («getCarManager отказал») легла бы ложная («соединение не поднялось»).

### Константы, скопированные из работающего кода

- `ID_HVAC_IN_OUT_TEMP = 675289370`, зона `InOutCAR_INSIDE = 1`
- формула датчика `(raw - 84) / 2 = °C`
- `raw < 0` — sentinel «нет данных», не температура (иначе `-1` покажется как
  −42.5 °C, то есть как исправный датчик)
- `IGNITION_STATE_ON = 4`; ACC, LOCK, OFF, START, UNDEFINED → выключить оба
  сиденья
- последовательность подключения: `Car.createCar` с `ServiceConnection` →
  `connect()` → `getCarManager` в `onServiceConnected` (как в
  `CarAvcManagerUtils`)

### Permissions

Сверено с обоими эталонами: у `changan_first-main/example` и у
`SeatHeat_v2-post056.apk` по **34** permission, наборы идентичны. У native —
**28**, строгое подмножество, ничего лишнего. Не взяты: `WAKE_LOCK`,
`VIBRATE`, `SCHEDULE_EXACT_ALARM`, `USE_FULL_SCREEN_INTENT`,
`FOREGROUND_SERVICE_LOCATION`, `com.wt.airconditioner.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`.

Четыре lint-замечания подавлены адресно через `tools:ignore` с объяснением
(`ACCESS_FINE_LOCATION` без COARSE; `WRITE_SETTINGS`,
`MOUNT_UNMOUNT_FILESYSTEMS`, `KILL_BACKGROUND_PROCESSES` как system-only) —
все они есть в оригиналах, а правила рассчитаны на публикацию в Play Store, не
на sideload в AAOS.

## Проверка

```bash
cd native-probe
./gradlew :app:testReleaseUnitTest   # 11 тестов
./gradlew lintRelease                # обязан проходить без ошибок
./gradlew :app:assembleRelease       # → AutoHeatProbe-v0.2-service-vc210.apk
```

Требуется JDK 17 и Android SDK 33. Flutter не нужен.

**Сделано на эмуляторе `UNI-S` (API 28, 1920×720 — как у головы):** UI
рендерится; кнопки работают; отсутствие `android.car` обрабатывается без
краша; сервис поднимается в foreground (id 888, канал `seat_heat`); после
«Назад» Activity закрыта, а сервис и процесс живы; при повторном открытии лог
восстанавливается из сервиса целиком; после `adb reboot` сервис стартует сам,
без запуска приложения.

**11 юнит-тестов** покрывают то, что без `android.car` не проверить: разбор
значения датчика (Number/String/мусор), решение «показывать ли температуру»
(sentinel не публикуется), правило зажигания. Тест sentinel проверен мутацией:
с убранным `raw < 0` он падает.

**Не проверено вживую и требует головы**: срабатывание зажигания, таймаут
подключения, приход sentinel с реального датчика.

## Этап 3: что делать дальше

**Тесты портируются первыми.** `lib/src/constants/temperature_constants.dart`
и `lib/src/services/auto_heat_service.dart` вместе со 143 dart-тестами — это
готовая исполняемая спецификация: каскад `3 → 2 → 1 → 0`, адаптивный step-down
по температуре, plan-key guard (после завершения каскада повторное событие с
той же температурой не перезапускает уровень 3), max-timer safety-net,
temperature-threshold гейт на старте пресета, `isPresetRunning` early-return.
Там чистая логика без Flutter, на JUnit ложится почти механически. Порт тестов
до порта кода — и поведение гарантированно не поплывёт.

**Хранение.** `shared_preferences` пишет в `FlutterSharedPreferences.xml` с
префиксом `flutter.` у ключей. Мигрировать настройки не нужно: голова одна,
пресетов пара штук, перенастроить руками дешевле любой миграции.

**Что смотреть в старом коде**: `lib/src/services/auto_heat_service.dart`,
`lib/src/constants/temperature_constants.dart`, `lib/src/models/preset.dart`,
`test/scenarios/walkthrough_log_test.dart`.

## Чего не делать

- Не менять `applicationId` — CarService не пустит к car API.
- Не добавлять `AccessibilityService` — он не нужен и был подозреваемым в
  проблемах на голове.
- Не убирать foreground-сервис — на Android 13+ процесс убьют.
- Не трогать формулу `(raw - 84) / 2` и правило `raw < 0`.
- Не выводить диагностику мимо экрана: adb к голове нет, logcat недоступен.
- Не урезать permission envelope без smoke-теста на голове.
