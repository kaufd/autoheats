# AutoHeat Probe — этап 1 миграции на native Android

Минимальное нативное приложение: читает температуру салона и переключает
подогрев обоих сидений. Первый этап поэтапного переписывания AutoHeat с
Flutter на native.

## Зачем

Пробник решает две задачи одновременно.

**Диагностика.** Flutter-сборки дают на голове белый экран. Гипотеза
(`WHITE_SCREEN_DIAGNOSTICS.md`) — свежий движок Flutter не рендерит на GPU
головы. Нативный UI рисуется системным View-стеком, поэтому пробник её
проверяет: если он показывает интерфейс, дело было в движке.

**Фундамент.** Если проверка проходит, этот же код становится основой для
этапов 2–4 (foreground-service и ignition → алгоритм и хранение → UI).

## Что намеренно отсутствует

Ни `AccessibilityService`, ни foreground-service. В Settings → Accessibility
голова показывает «сервис работает неправильно» ещё до запуска приложения —
если бы сервис был в пробнике, неудачу нельзя было бы отличить от проблемы
рендера. Одна переменная за раз.

`AccessibilityService` в native не нужен и на последующих этапах: во
Flutter-версии он существовал только чтобы поднимать background isolate, а
foreground-service плюс `RECEIVE_BOOT_COMPLETED` покрывают это сами.

## Сборка

```bash
cd native-probe
./gradlew :app:assembleRelease
# → app/build/outputs/apk/release/AutoHeatProbe-v0.1-probe-vc200.apk (~175 KB)

./gradlew :app:testReleaseUnitTest   # разбор значения датчика
./gradlew lintRelease                # обязан проходить без ошибок
```

Требуется JDK 17 и Android SDK 33. Flutter не нужен — проект самостоятельный
и никак не связан с корневым `pubspec.yaml`.

## Проверка на голове

Порядок как обычно: uninstall предыдущего → reboot головы → install через
файловый менеджер.

`applicationId` = `com.wt.airconditioner`, тот же, что у Flutter-версии на
ветке `fix/package-name`: с другим именем CarService не отдаёт
`CarHvacManager` (`SecurityException "… is not in white list!"`). Рядом с
Flutter-сборкой пробник поэтому не встанет — только вместо неё.

Весь диагностический вывод идёт **на экран**, в правую панель — adb-доступа к
голове нет. Кнопка «Копировать лог» кладёт его в буфер обмена.

## Как читать результат

| Что на экране | Вывод |
|---|---|
| Интерфейс виден, статус «HVAC подключён», температура читается | Этап 1 пройден. Виноват был движок Flutter, идём на этап 2 |
| Интерфейс виден, статус «HVAC недоступен» | Рендер починен, но car API не отдаётся — смотреть текст ошибки в логе |
| В логе `SecurityException … is not in white list!` | Голова не пускает пакет к car API; имя пакета или его whitelist-статус |
| Белый/пустой экран, приложение не стартует | Дело **не** во Flutter. Переписывание отменяется, причина системная |
| Статус «HVAC недоступен», в логе `ТАЙМАУТ 10 с` | `connect()` прошёл, но `onServiceConnected` не пришёл — CarService не поднял соединение |
| Температура не появляется, в логе `sentinel raw=-1` | Связь с HVAC есть, данных с датчика нет — это не поломка пробника |

Температура намеренно не показывается при `raw < 0` и при неразбираемом
значении: `-1` дало бы «−42.5 °C», а это ложный вывод об исправном датчике.
Правило то же, что в `HvacService._isInvalidRawTemperature`.

## Проверено

На эмуляторе `UNI-S` (API 28, 1920×720 — как у головы): UI рендерится,
кнопки работают, отсутствие `android.car` обрабатывается без краша (статус
краснеет, лог показывает причину). Разбор значения датчика и решение
«показывать ли температуру» покрыты юнит-тестами (8 тестов) — на эмуляторе
этот путь недостижим, а на голове выполняется вслепую. `lintRelease` проходит
без ошибок.

Настоящий HVAC на эмуляторе проверить нельзя — там нет `android.car`, это
делает только реальная голова. По той же причине не проверяются вживую
таймаут подключения и обработка sentinel: их поведение задано кодом и
описано в таблице выше.

## Permissions

Сверено с обоими эталонами: у `changan_first-main/example` и у
`SeatHeat_v2-post056.apk` по **34** permission, идентичный набор. У пробника
**24** — строгое подмножество, ничего лишнего. Убрано только то, чего на
этапе 1 нет физически: foreground-service, boot, уведомления, будильники,
вибрация, wake lock.

Lint ругается на три из оставшихся (`ACCESS_FINE_LOCATION` без COARSE,
`WRITE_SETTINGS`, `MOUNT_UNMOUNT_FILESYSTEMS`, `KILL_BACKGROUND_PROCESSES` —
system-only). Все они присутствуют в оригиналах, поэтому подавлены адресно
через `tools:ignore` с объяснением, а не удалены: правила рассчитаны на
публикацию в Play Store, здесь же sideload на AAOS, где envelope доказанно
работает.

## Устройство

| Файл | Роль |
|---|---|
| `CarHvacProbe.java` | мост к `android.car`: подключение, чтение температуры, установка уровня |
| `MainActivity.java` | экран, кнопки, лог на экране |
| `app/libs/android.car.jar` | стаб для компиляции, копия из `packages/android_automotive_plugin` |

Последовательность подключения (`Car.createCar` с `ServiceConnection` →
`connect()` → `getCarManager` в `onServiceConnected`) повторяет
`CarAvcManagerUtils` из рабочего плагина — это единственный путь, про который
известно, что он работает на голове Changan.

Константы: `ID_HVAC_IN_OUT_TEMP = 675289370`, зона `InOutCAR_INSIDE = 1`,
формула датчика `(raw - 84) / 2 = °C` — те же, что в `HvacService`.
